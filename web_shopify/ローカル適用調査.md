# Shopifyサイト作成をローカルから適用する方法の調査

調査日: 2026-04-28
最終更新日: 2026-04-30

## 結論

ローカルからの適用は可能ですが、対象によって手段を分ける必要があります。

| 対象 | ローカル適用手段 | 実現性 | 備考 |
| --- | --- | --- | --- |
| テーマコード | Shopify CLI `theme push` | 高 | `web_shopify/` のLiquid、JSON template、CSS、JSを反映できる |
| テーマZIP | Shopify CLI `theme package` または管理画面アップロード | 高 | 初回アップロード・バックアップ用途 |
| 商品・コレクション | Admin REST API + GraphQL Admin API | 高 | 商品・画像・コレクションはREST、公開はGraphQL |
| 固定ページ | Admin REST API `/pages` | 高 | template suffixも指定可能 |
| ブログ記事 | Admin REST API `/blogs` / `/articles` | 中 | ブログ作成・記事登録はAPIで可能 |
| メニュー | GraphQL Admin API `menuCreate` / `menuUpdate` | 中 | `write_online_store_navigation` scopeが必要 |
| メタフィールド定義 | GraphQL Admin API `metafieldDefinitionCreate` | 高 | 商品・ページ用定義を自動作成可能 |
| 商品・記事・コレクション画像 | Admin REST API画像attachment | 中 | seedではローカル画像をbase64 attachmentとして登録する |
| 決済・配送・法務設定 | 管理画面操作 | 低 | 自動化対象にしない方が安全 |

今回登録したCatalog / Storefront APIキーは、商品取得やStorefront API連携向けのキーとして扱います。商品作成、ページ作成、テーマ反映には、Dev DashboardアプリのClient credentials grantまたはShopify CLI / Theme Access tokenを使います。

2026-04-30時点では、テーマ反映はShopify CLI `theme push`、商品・コレクション・固定ページ・BLOG・記事・メニュー・主要metafield定義・初期SEOメタデータ・画像altの投入は `web_shopify/scripts/seed-shopify.mjs` で補助できる状態です。

## 秘密情報の配置

実値は以下に保存します。

```txt
env/shopify/.env.local
```

このファイルは `.gitignore` で除外済みです。共有用テンプレートは以下です。

```txt
env/shopify/.env.example
```

PowerShellで一時的に読み込む例:

```powershell
Get-Content ..\env\shopify\.env.local |
  Where-Object { $_ -and $_ -notmatch '^\s*#' } |
  ForEach-Object {
    $name, $value = $_ -split '=', 2
    [Environment]::SetEnvironmentVariable($name, $value, 'Process')
  }
```

`web_shopify/` から実行する場合は `..\env\shopify\.env.local` を参照します。

## 1. テーマコードの反映

テーマはShopify CLIで反映できます。

```powershell
cd D:\Works\project\KanpoSite\web_shopify

shopify auth login --store $env:SHOPIFY_STORE_DOMAIN
shopify theme list --store $env:SHOPIFY_STORE_DOMAIN
shopify theme push --store $env:SHOPIFY_STORE_DOMAIN --theme $env:SHOPIFY_THEME_ID --path . --nodelete --allow-live
```

未公開テーマとして新規アップロードする場合:

```powershell
shopify theme push --store $env:SHOPIFY_STORE_DOMAIN --path . --unpublished --json
```

公開までCLIで行う場合:

```powershell
shopify theme push --store $env:SHOPIFY_STORE_DOMAIN --path . --unpublished --json
shopify theme publish --store $env:SHOPIFY_STORE_DOMAIN --theme $env:SHOPIFY_THEME_ID
```

Theme Access appまたはAdmin API tokenを使う場合、`SHOPIFY_CLI_THEME_TOKEN` を使えます。

```powershell
shopify theme push --store $env:SHOPIFY_STORE_DOMAIN --password $env:SHOPIFY_CLI_THEME_TOKEN --theme $env:SHOPIFY_THEME_ID --path . --nodelete --allow-live
```

注意点:

- `theme push` はリモートテーマを上書きします。
- 本番テーマへ直接反映する場合は `--allow-live` が必要になることがあります。
- 安全運用では、未公開テーマへpush、プレビュー確認、公開の順にします。

## 2. 管理画面データの投入

商品、ページ、コレクション、ブログ、メニュー、メタフィールドはテーマCLIではなくAdmin APIで投入します。現行seedは商品・ページ・ブログ・メタフィールド値をREST Admin API、メニュー・公開・metafield定義をGraphQL Admin APIで処理します。

必要な代表scope:

| 操作 | 代表scope |
| --- | --- |
| 商品作成 | `write_products` |
| 商品画像 | `write_products` |
| コレクション作成 | `write_products` |
| 商品・コレクションのOnline Store公開 | `read_publications`、`write_publications` |
| 固定ページ作成・更新 | `read_content`、`write_content`、必要に応じて `read_online_store_pages` |
| ブログ・記事作成・更新 | `read_content`、`write_content` |
| メニュー作成 | `write_online_store_navigation` |
| メタフィールド定義 | 対象namespace / resource typeへのアクセス |

Admin APIのエンドポイント:

```txt
https://{store}.myshopify.com/admin/api/2026-04/{resource}.json
https://{store}.myshopify.com/admin/api/2026-04/graphql.json
```

HTTPヘッダー:

```txt
Content-Type: application/json
X-Shopify-Access-Token: {SHOPIFY_ADMIN_ACCESS_TOKEN}
```

このプロジェクトの現行スクリプトでは固定Admin API tokenではなく、`SHOPIFY_DEV_CLIENT_ID` と `SHOPIFY_DEV_CLIENT_SECRET` から実行時にaccess tokenを取得します。

## 3. Shopify CLI `app execute` の使いどころ

Shopify CLIにはAdmin GraphQLを実行する `shopify app execute` があります。

```powershell
shopify app execute `
  --store $env:SHOPIFY_STORE_DOMAIN `
  --version 2026-04 `
  --query-file .\graphql\pageCreate.graphql `
  --variable-file .\data\pages\kominka.json
```

ただし公式ドキュメント上、`app execute` のmutationは開発ストアに限定されます。通常の本番ストアへデータ投入する運用では、Admin API access tokenを使ったローカルスクリプトの方が現実的です。

## 4. 推奨する自動化構成

### Phase 1: テーマ反映のみCLI化

目的: いまのZIPアップロードをCLIに置き換える。

必要情報:

- `SHOPIFY_STORE_DOMAIN`
- `SHOPIFY_THEME_ID`
- CLIログイン、または `SHOPIFY_CLI_THEME_TOKEN`

成果:

- `shopify theme push` でテーマを反映
- `shopify theme check` でLiquid/themeチェック
- `shopify theme package` で従来どおりZIPも作成可能

### Phase 2: 商品・ページのseedスクリプト化

目的: `ページ作成フロー.md` の手作業を一部自動化する。

現行構成:

```txt
web_shopify/
  scripts/
    seed-shopify.mjs
```

実行方法:

```powershell
cd D:\Works\project\KanpoSite\web_shopify
node scripts\seed-shopify.mjs
```

処理順:

1. `.env.local` を読み込む
2. Client credentials grantでAdmin API access tokenを取得する
3. 主要metafield定義を作成またはpinする（権限不足時はログ出力して続行）
4. 商品をhandleで検索し、作成または更新する
5. 商品metafields、SEO title / description、画像altを設定する
6. コレクションをhandleで検索し、作成または更新する
7. コレクションのSEO title / description、代表画像altを設定する
8. 固定ページをhandleで検索し、作成または更新する
9. 固定ページのSEO title / descriptionとpage metafieldsを設定する
10. BLOG `stories` と記事を作成または更新し、SEO title / description、記事画像altを設定する
11. `main-menu` と `footer` を更新する
12. 商品とコレクションをOnline Storeへ公開する

注意:

- 画像アップロードはAPI手順が複数段階になるため、初回は管理画面登録の方が早い場合があります。
- 既存データの重複作成を避けるため、handleで検索して存在確認してから作成する実装が必要です。
- 商品価格や在庫、配送、決済は本番影響が大きいため、初回は手動確認を挟みます。

### Phase 3: 本番適用

本番適用は以下の順にします。

1. 開発ストアまたは未公開テーマに反映
2. プレビュー確認
3. 商品・ページ投入結果を管理画面で確認
4. テーマ公開
5. 決済、配送、ポリシー、問い合わせフォーム送信確認

## 5. このプロジェクトでの判断

短期的には以下が妥当です。

1. テーマコードはShopify CLI `theme push` で反映する。
2. 商品・ページ・BLOG・メニュー・主要metafield定義・初期SEOメタデータの投入は `scripts/seed-shopify.mjs` で補助する。
3. 決済、配送、法務、通知先メール、ドメイン、GA4、Search Console、問い合わせの受信確認は管理画面で手動確認する。
4. Catalog / Storefront APIキーは商品作成用途ではなく、公開データ取得用途として扱う。

## Dev Dashboardアプリが無い場合

Catalog APIキーはDev DashboardのCatalog機能で発行されますが、商品・ページ・メニューをAdmin APIで自動投入するための「アプリ」とは別です。対象アプリが無い場合は、Dev DashboardでAPI-only用途のアプリを新規作成し、ストアへインストールします。

手順:

1. `dev.shopify.com/dashboard` を開きます。
2. 左メニューの `Apps` を開きます。
3. `Create app` をクリックします。
4. `Start from Dev Dashboard` を選択します。
5. アプリ名を `KanpoSite Admin Seed` などにして作成します。
6. `Versions` でバージョンを作成します。
7. App URLは管理画面UIを持たない自動化用途なら、公式ドキュメントの案内どおりデフォルトURLを使えます。
8. 必要scopeを設定します。
   - `read_products`
   - `write_products`
   - `read_content`
   - `write_content`
   - `read_online_store_pages`
   - `read_online_store_navigation`
   - `write_online_store_navigation`
   - `read_publications`
   - `write_publications`
   - Metafield値・Metafield定義は、Product / Page / Blogなど対象リソースのscopeで操作します。
   - `read_metaobject_definitions` / `write_metaobject_definitions` / `read_metaobjects` / `write_metaobjects`
     はFAQ等をMetaobjectsへ拡張する場合のみ追加します。
9. `Release` します。
10. `Home > Install app` から `cqs1ru-bs.myshopify.com` にインストールします。
11. `Settings` で `Client ID` と `Client secret` を取得し、`env/shopify/.env.local` の `SHOPIFY_DEV_CLIENT_ID` と `SHOPIFY_DEV_CLIENT_SECRET` に保存します。

Dev DashboardのClient ID / Secret方式では、Shopify管理画面に固定Admin API tokenは表示されません。ローカルスクリプトが実行時にClient credentials grantで24時間有効なaccess tokenを取得します。
