## 1. 目的

`web_mock/` は依頼者レビュー用の静的モックアプリであり、フェーズ1からフェーズ2でデザイン方向と主要導線を固めるために使用する。

- 実データ接続は行わない
- `microCMS`、`Shopify`、`contact-api/` には接続しない
- 承認済み UI を後続フェーズで `web/` へ移植する

## 2. 前提条件

- 参考デザイン
  - `https://www.roccadeifiori.eu/en/the-company/`
- 環境参照元
  - `env/.env.deploy`
- `env/.env.deploy` の `DEPLOY_SITE_URL` は公開サイトの基準 URL として扱い、`web_mock/` の文言や遷移設計の参照先に利用する
- `web_mock/` 自体の確認 URL は `NEXT_PUBLIC_MOCK_SITE_URL` で管理する

## 3. デザイン方針

参考サイトの雰囲気をそのまま複製せず、以下の要素だけを取り込む。

- 画面上部で印象を決めるフルブリードのヒーロー
- セリフ体見出しと細いサンセリフ本文の組み合わせ
- 深緑、生成り、土色、金茶を基調とした配色
- 写真を大きく見せる余白設計とフレーム表現
- CTA を少数に絞った静かな導線

`web_mock/` では実画像が未確定でもレビュー可能なように、初期段階はグラデーションとプレースホルダーパネルで構成する。

## 6. レビュー観点

- 第一印象が「漢方」「農園」「古民家」に自然につながるか
- 商品導線と古民家導線の優先順位が分かるか
- 写真が入ったときに映える余白と比率になっているか
- フォームや CTA が営業色過多になっていないか
- `web/` へ移植しやすい粒度で部品化できているか

## 7. 次の実装順

1. 実画像を差し込めるよう `PhotoPanel` を実画像対応へ拡張する
2. 依頼者レビューで不要な導線と過剰な情報量を削る
3. 承認済み UI を `web/` のテンプレート群へ移植する
4. その後に `microCMS` / `Shopify` 連携へ進む
