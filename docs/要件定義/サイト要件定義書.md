## 1. プロジェクト概要

### 1.1 プロジェクト名

漢方ブランド 公式サイト（KanpoSite）

### 1.2 プロジェクト背景

日本の伝統的な漢方・薬草文化を現代に伝えるブランドとして、商品販売だけでなく、ブランド背景、畑・栽培環境、古民家体験、読み物コンテンツを一体で発信する公式サイトを構築する。  
本サイトは単なる会社案内や単独ECではなく、ブランド体験全体を伝えるための情報発信基盤として位置付ける。

### 1.3 プロジェクト目的

- 漢方商品のオンライン販売を実現する
- ブランドのストーリー、理念、栽培背景を継続的に発信する
- 古民家・地域体験の認知向上と予約導線を構築する
- 商品SEO、記事SEO、地域SEOの3系統で検索流入を獲得する
- 運営者がコードを触らずに記事、FAQ、写真、古民家情報を更新できる運用を実現する
- 将来的な多言語対応や会員機能追加に備えた拡張性を確保する

### 1.4 採用方針

| 領域 | 採用方針 |
|---|---|
| フロントエンド | `Next.js App Router` |
| CMS | `microCMS` |
| EC | `Shopify` |
| 商品取得 | `Shopify Storefront API`（ビルド時取得 / 必要に応じてクライアントサイド取得） |
| ホスティング | `ConoHa WING` |
| 出力方式 | `Next.js Static Export`（`output: 'export'`）。ISR / Server Actions は使用しない |
| 解析 | `Google Search Console`、`GA4` |
| 予約導線 | `Facebook` または外部予約サービスへのリンク |

### 1.5 対象サイトURL（予定）

- 本番: https://（ドメイン未定）
- 配信基盤: `ConoHa WING`

## 2. 想定ユーザー（ターゲット）

### 2.1 メインターゲット

| ターゲット区分 | 詳細 |
|---|---|
| 国内・健康意識の高い30〜60代女性 | 漢方・薬草・自然療法に関心があり、食や生活にこだわりを持つ層 |
| 国内・贈答需要層 | 両親・友人への贈り物として自然派・国産ブランド品を探している層 |
| 農業・ハーブ・薬草に関心のある若年層 | 農的暮らし、薬草文化、体験型コンテンツに興味を持つ20〜40代 |
| 地域体験・古民家滞在に関心のある旅行者 | 宿泊、見学、里山体験を求める層 |

### 2.2 サブターゲット

- 飲食業、薬局、サロン等のB2B購入者
- 海外在住日本人、将来的なインバウンド訪問者

### 2.3 ユーザーの主な課題・ニーズ

- 信頼できる国産・自然由来の商品を探している
- 商品の原材料、栽培背景、世界観を理解したうえで購入したい
- 体験や滞在も含めてブランド全体を知りたい
- 検索で見つけた記事や施設情報から、商品や予約導線へ自然に移動したい

## 3. サイト構成方針

### 3.1 サイトの役割区分

本サイトは以下の3系統で構成する。

- ブランド・集客導線
  - ブランド紹介
  - コンセプト
  - 畑紹介
  - ストーリー
  - お知らせ
- 商品・販売導線
  - 商品一覧
  - 商品カテゴリ
  - 商品詳細
  - FAQ
  - 配送情報
  - 返品情報
- 古民家・地域導線
  - 古民家紹介
  - 体験案内
  - アクセス
  - 周辺導線
  - Facebook予約導線

### 3.2 データ責務の分離

| システム | 主な責務 |
|---|---|
| `Shopify` | 商品主データ、価格、在庫、コレクション、カート、チェックアウト、注文管理 |
| `microCMS` | ストーリー、お知らせ、FAQ、畑情報、古民家情報、トップ特集枠、固定文言の一部、SEO補助文言 |
| `Next.js` | 画面描画、ルーティング、SEO制御、構造化データ、内部リンク、パンくず、表示テンプレート |

### 3.3 運用前提

- 商品主データは `Shopify` を正本とし、`microCMS` に重複保持しない
- 記事、FAQ、古民家、畑、特集情報は `microCMS` を正本とする
- 運営者は日常更新を `Shopify` と `microCMS` の管理画面で行う
- 開発側は `Next.js` のレイアウト、表示ロジック、SEOロジックを管理する

## 5. 機能要件

### 5.1 トップページ機能

- ブランドイメージを伝えるファーストビュー
- キャッチコピー、ブランドメッセージ、主要導線の配置
- 注目商品、新着商品、季節特集の表示
- ストーリー、お知らせ、畑、古民家への導線表示
- 運営者がCMSから差し替え可能な特集枠、バナー、写真の表示
- 商品ページ、読み物ページ、古民家ページへの内部リンク最適化

### 5.2 商品販売機能

#### 商品一覧・カテゴリ

- `Shopify` の商品とコレクションを取得して一覧表示する
- 商品カードに商品名、価格、在庫状態、サムネイルを表示する
- カテゴリ別ページを持ち、一覧ページから遷移できるようにする
- 絞り込み・並び順のUIを提供する。絞り込み軸の基本方針は以下とする
  - カテゴリ: `Shopify` コレクションを基準とする
  - 在庫状況: 在庫あり / 在庫なし の表示切り替えを提供する
  - 並び順: 新着順・価格昇順・価格降順を提供する。詳細な選択肢は基本設計書で定める

#### 商品詳細

- 商品名、短い説明、詳細説明、価格、在庫状況を表示する
- 商品画像を複数枚表示する
- 原材料、飲み方、注意事項、FAQを表示する
- 関連商品を表示する
- 配送情報、返品情報への導線を設ける
- `Product` / `Offer` 構造化データ出力に必要な項目を保持する

#### 購買導線

- 商品詳細から `Shopify` カート追加または `Shopify checkout` へ遷移できること
- 決済、在庫、注文管理は `Shopify` に委譲すること
- 独自の決済処理や独自注文管理はフェーズ1では実装しないこと

### 5.3 ブランド・コンテンツ機能

#### ブランド紹介・コンセプト

- ブランド紹介ページとコンセプトページを分離する
- ブランドの背景、理念、こだわり、代表メッセージを掲載する
- 画像と文章をCMSで更新できるようにする

#### 畑紹介

- 畑・農場の紹介文と写真ギャラリーを表示する
- 栽培している素材、季節ごとの様子、こだわりを掲載する
- 地図や所在地情報を表示する

#### ストーリー・お知らせ

- `stories` と `news` を分けて運用する
- 一覧と詳細ページを持つ
- ストーリー詳細では関連商品や古民家ページへの導線を表示する
- SEO用のタイトル、ディスクリプション、サムネイル画像を管理できるようにする

#### FAQ

- 独立した `/faq` ページを設ける
- 商品、配送、古民家、問い合わせなどのFAQを掲載できるようにする

### 5.4 古民家・地域訴求機能

- 古民家紹介、アクセス、体験案内をページ分割して提供する
- 施設名、写真、所在地、アクセス、駐車場、予約方法、周辺案内を掲載する
- 体験内容、過ごし方、FAQを掲載する
- Facebookまたは外部予約サービスへのリンクを `/kominka` および `/kominka/experience` に掲載する
- 予約導線は独立ページではなく、古民家関連ページ内の外部リンクとして提供する
- `LocalBusiness` または `LodgingBusiness` 系構造化データ出力を想定した情報を保持する

### 5.5 お問い合わせ・法務機能

- 問い合わせフォームを提供する
- フォームには問い合わせ種別、氏名、メールアドレス、本文を含める
- フォームの入力バリデーションは以下を基本方針とする。詳細は基本設計書で定める
  - 問い合わせ種別、氏名、メールアドレス、本文は必須項目とする
  - メールアドレスは形式検証を行う
  - 本文は最大 1,000 文字を上限とする
  - 電話番号フィールドは任意項目として設ける
- フォーム送信は外部フォームサービスまたは別途 API 層経由で処理する（Static Export 制約のためサイト内サーバーサイド API は使用不可）
- 問い合わせ内容はメール通知または問い合わせ管理基盤へ連携できること
- 使用する送信サービス、API 実装方式、通知先管理方法は基本設計書で定める
- フォーム送信 API にはスパム対策を適用する
- フェーズ1では `honeypot`、送信頻度制御、許可オリジン検証等を基本とし、必要に応じて外部 CAPTCHA を追加できる構成とする
- 配送情報、返品情報、特商法表記、プライバシーポリシー、利用規約を独立ページとして設ける

### 5.6 CMS・外部連携機能

- `microCMS` と `Shopify` それぞれのAPI連携を実装する
- `microCMS` の下書き確認機能を設ける
- `microCMS` 更新時は Webhook をトリガーとして再ビルド + デプロイを実行することでサイトへ反映する（Static Export のため revalidate は使用しない）
- `Shopify` 側の商品データ更新時も Webhook をトリガーとして再ビルド + デプロイを実行する。在庫状況等のリアルタイム性が必要な表示はクライアントサイドからの取得を検討し、詳細は基本設計書で定める
- `microCMS` および `Shopify` の API がビルド時に応答しない場合のエラーハンドリング方針は基本設計書で定める。本番サイトは直前のビルド済みファイルが維持される
- 環境変数で各種APIキー、トークン、ドメインを管理する

### 5.7 共通機能

- レスポンシブデザイン
- グローバルナビゲーション
- フッター
- パンくずリスト
- 404ページ
- OGP設定
- サイトマップ生成
- robots.txt 設定

## 6. コンテンツ・データ要件

### 6.1 `microCMS` で管理する主なコンテンツ

- ストーリー
- お知らせ
- FAQ（共通FAQ・商品関連FAQを含む）
- 畑紹介
- 古民家紹介
- 古民家アクセス
- 古民家体験
- トップ特集枠
- サイト共通設定

### 6.2 `Shopify` で管理する主なデータ

- 商品
- 商品画像
- 商品カテゴリ（コレクション）
- 価格
- 在庫
- バリエーション
- チェックアウト設定
- 配送設定

### 6.3 商品ページで必要な項目

以下の項目を商品詳細ページに表示する。各項目の主データソースと実装方針を示す。

| 表示項目 | 主データソース | データ項目 / 実装方針 | 補足 |
|---|---|---|---|
| 商品名 | Shopify | `title` | 標準フィールド |
| 短い説明 | Shopify | `metafields.details.short_description` | メタフィールドとして定義 |
| 詳細説明 | Shopify | `descriptionHtml` | 標準フィールド |
| 価格 | Shopify | `priceRange.minVariantPrice` | 標準フィールド |
| 在庫状況 | Shopify | `availableForSale` | 標準フィールド |
| 内容量 | Shopify | `metafields.details.volume` | メタフィールドとして定義 |
| 原材料 | Shopify | `metafields.details.ingredients` | メタフィールドとして定義 |
| 飲み方 | Shopify | `metafields.details.how_to_use` | メタフィールドとして定義 |
| 注意事項 | Shopify | `metafields.details.caution` | メタフィールドとして定義 |
| FAQ | microCMS | FAQ コンテンツを商品 slug または Shopify handle と紐付けて管理する | 商品FAQも `microCMS` を正本とする |
| 画像複数枚 | Shopify | `images` | 標準フィールド |
| 関連商品 | Shopify | `metafields.details.related_products` またはコレクション連携 | 実装方式は基本設計書で定める |

### 6.4 CMS項目で必要なSEO補助情報

- `seoTitle`
- `seoDescription`
- OGP画像
- OGP画像の代替テキスト
- `slug`
- 公開日
- 更新日

### 6.5 microCMS コンテンツ型（スキーマ）方針

各コンテンツの詳細なフィールド定義（型、必須可否、バリデーション）は「サイト詳細設計書.md」で別途定める。  
本ドキュメントでは各コンテンツ型の名称と必須フィールドの方向性のみを規定する。コンテンツ型の命名は英語スネークケースとする（例: `story`, `news`, `faq`, `farm_page`, `kominka_page`）。

各コンテンツ型の主な必須フィールドの方向性は以下のとおり。

| コンテンツ型 | 主な必須フィールド |
|---|---|
| `story` | `title`, `slug`, `body`（リッチテキスト）, `publishedAt`, `seoTitle`, `seoDescription`, `ogpImage` |
| `news` | `title`, `slug`, `body`（リッチテキスト）, `publishedAt` |
| `faq` | `question`, `answer`, `category`（商品 / 配送 / 古民家 / その他）, `relatedProductSlug`（任意） |
| `farm_page` | `title`, `body`（リッチテキスト）, `images`（複数） |
| `kominka_page` | `name`, `description`, `images`（複数）, `address`, `reservationUrl` |
| `kominka_access` | `address`, `mapEmbedUrl`, `parking`, `accessNote` |
| `kominka_experience` | `title`, `body`（リッチテキスト）, `images`（複数）, `reservationUrl` |
| `top_feature` | `title`, `image`, `linkUrl`, `publishedAt`, `expiresAt`（任意） |
| `site_settings` | `siteName`, `siteDescription`, `homeHeroTitle`, `homeHeroLead`, `homeHeroImage`, `homeIntroText`, `ogpDefaultImage`, `logo`, `contactEmail`, `socialLinks` |

## 7. SEO要件

### 7.1 共通SEO要件

- 全ページに `title`、`description`、`canonical` を設定する
- OGPタグを設定する
- パンくずを構造化データを含めて出力する
- `sitemap.xml` を生成する
- `robots.txt` を設定する
- 内部リンクをトップ、記事、商品、古民家間で整理する
- 構造化データの出力対象ページと型の方針は以下とする。詳細なスキーマ設計は基本設計書で定める

| 対象ページ | 構造化データ型 |
|---|---|
| 全ページ共通 | `WebSite`、`Organization` |
| 全ページ（パンくず） | `BreadcrumbList` |
| 商品詳細 | `Product`、`Offer` |
| ストーリー詳細 | `Article` |
| FAQページ | `FAQPage` |
| 古民家関連ページ | `LodgingBusiness`（宿泊を伴う場合）または `LocalBusiness`（日帰り体験のみの場合）。基本設計書で確定 |

### 7.2 商品SEO要件

- 商品詳細ページに `Product` と `Offer` の構造化データを出力する
- 商品名、価格、在庫、画像、説明を検索エンジンが理解しやすい形で表示する
- 商品カテゴリページをインデックス対象とする
- 配送情報と返品情報への導線を商品詳細から明示する

### 7.3 記事SEO要件

- ストーリー詳細に `Article` 構造化データを出力する
- 公開日、更新日、著者または運営主体を表示できるようにする
- 関連商品、関連古民家ページへの内部リンクを設ける

### 7.4 古民家・地域SEO要件

- 古民家ページに構造化データを出力できるようにする。宿泊を伴う場合は `LodgingBusiness`、日帰り体験のみの場合は `LocalBusiness` を基本とし、詳細は基本設計書で確定する
- 施設名、住所、地図、画像、予約導線を明示する
- アクセスページ、体験ページを独立させて地域検索ニーズに対応する

### 7.5 画像SEO要件

- 画像には説明的なファイル名を付与する
- すべての主要画像に `alt` テキストを設定する
- 画像周辺に文脈となるテキストやキャプションを配置できる構成にする
- Static Export のため `next/image` の自動最適化（Vercel Image Optimization）は使用しない
- 商品画像は `Shopify` CDN から配信されるため、Shopify 側の画像変換機能（WebP配信等）を活用する
- CMS 管理の画像は WebP 形式を優先して登録し、`microCMS` の画像変換オプションを活用する
- 画像最適化の具体的な実装方針は基本設計書で定める

## 8. 非機能要件

### 8.1 パフォーマンス要件

| 項目 | 目標値 |
|---|---|
| LCP | 2.5秒以内 |
| FCP | 1.8秒以内 |
| CLS | 0.1以下 |
| Lighthouse Performance | 85点以上 |
| Lighthouse SEO | 95点以上 |

### 8.2 セキュリティ要件

- HTTPS 常時SSLとする
- フォーム送信にはスパム対策を適用する（セクション 5.5 参照）
- フォーム送信 API エンドポイントには IP ベースまたは同等の送信頻度制御を実装すること
- `Shopify` の決済情報をサイト側で保持しない
- APIキー、アクセストークン、Webhookシークレットは環境変数で管理する
- 公開不要なトークンを `NEXT_PUBLIC_` 付きで公開しない
- 依存パッケージを継続的に更新する
- セキュリティヘッダー（`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy` 等）の設定方針は基本設計書で定める

### 8.3 アクセシビリティ要件

- `WCAG 2.1 AA` 準拠を目標とする
- キーボード操作で主要導線に到達できること
- スクリーンリーダー利用を考慮したラベル付けを行うこと
- テキストコントラスト比は 4.5:1 以上を目標とする
- フォーム、画像、リンクに適切な補助情報を付与すること

### 8.4 ブラウザ・デバイス対応

| 対象 | 詳細 |
|---|---|
| モバイル | iOS Safari / Android Chrome の最新2バージョン |
| PCブラウザ | Chrome / Firefox / Safari / Edge の最新2バージョン |
| 画面サイズ | 375px から 1920px を想定 |

### 8.5 インフラ・運用要件

- 配信基盤は `ConoHa WING` を前提とし、`Next.js Static Export` によるビルド済み静的ファイルをデプロイする
- `microCMS` および `Shopify` の Webhook をトリガーとした自動再ビルド + デプロイのパイプラインを整備する
- `Shopify Storefront API` を用いてビルド時に商品データを取得できること
- ステージング・確認用環境の構築方針（ブランチデプロイ等の代替手段を含む）は基本設計書で定める
- `Google Search Console` と `GA4` を導入できること
- GA4 で計測する主要コンバージョンイベント（商品閲覧、購入導線クリック、問い合わせ送信、古民家予約リンククリック等）の設計は基本設計書で定める
