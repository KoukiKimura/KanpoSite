## 1. 運用ルール

- 本ファイルは開発進捗の正本として扱う
- タスク着手時に `未着手` を `進行中` に更新する
- 完了時はチェックボックスを更新し、必要に応じて完了日を記録する
- 依頼者確認が必要な項目は、確認待ちと承認済みを明記する
- 大きな方針変更が発生した場合は「判断メモ」に追記する

### 1.1 ステータス定義

| ステータス | 意味 |
|---|---|
| `未着手` | まだ開始していない |
| `進行中` | 実作業中 |
| `確認待ち` | 依頼者または運営者の確認待ち |
| `完了` | 完了済み |
| `保留` | 外部要因または判断待ちで停止中 |

## 6. 第2案への切替判定

以下のいずれかに該当した場合、第2案 `Vercel Functions + Resend` への切替検討を行う。

- [ ] `ConoHa` メール送信の到達率に継続的な問題がある
- [ ] スパム流入が増加し、`honeypot` と送信頻度制御だけでは対応が難しい
- [ ] API ログ、障害調査、保守負荷が開発体制に対して重い
- [ ] ステージングと本番で問い合わせ API の差分管理が負担になっている
