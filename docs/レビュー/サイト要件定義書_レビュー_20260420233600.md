## 総合評価

**評価: A-（要件定義書として主要な不整合は解消済み）**

`Next.js + microCMS + Shopify` を前提とした責務分離、SEO方針、主要ルーティング、フェーズ管理の方向性は妥当であり、実装着手の前提として使える状態まで整理された。  
今回のレビューでは、ページ一覧と機能要件の境界、FAQ の正本、商品詳細データのマッピング、問い合わせ機能の記述粒度を中心に見直した。

---

## 主な指摘と対応結果

### 1. ページ一覧に「ページではないもの」が含まれていた

**指摘内容**

- 旧版では予約導線が `P17` としてページ一覧に含まれていた
- ただし内容は「`/kominka` ページ内の外部リンク」であり、独立ページ定義ではなかった

**対応結果**

- 要件定義書のページ一覧から予約導線専用ページを削除
- 予約導線は `/kominka` および `/kominka/experience` 内に配置する機能要件へ整理
- 正規ルーティング一覧からも独立ページ定義を外した

### 2. FAQ の正本が `Shopify` と `microCMS` で揺れていた

**指摘内容**

- 要件定義書の責務分離では FAQ は `microCMS` 管理
- 一方、商品詳細項目では `Shopify metafield` と `microCMS` の選択式になっていた

**対応結果**

- FAQ は `microCMS` を正本に統一
- 商品詳細ページの FAQ も `microCMS` 側の FAQ コンテンツを参照する方針に統一
- `microCMS` 管理コンテンツに「共通FAQ・商品関連FAQを含む」ことを明記

### 3. 商品説明の Shopify マッピングが成立していなかった

**指摘内容**

- 旧版では「短い説明」に `description`、「詳細説明」に `descriptionHtml` を割り当てていた
- しかし `descriptionHtml` は `description` の HTML 表現であり、別入力項目ではない

**対応結果**

- 「短い説明」は `metafields.details.short_description`
- 「詳細説明」は `descriptionHtml`
- としてデータモデルを分離
- あわせて表の見出しを「Shopify フィールド」から「主データソース / 実装方針」へ変更し、`microCMS` 管理項目も混在できるよう整理

### 4. 問い合わせ機能の記述が要件定義書として細かすぎた

**指摘内容**

- 旧版では `Vercel Functions`、`Resend`、`SendGrid` が要件定義書に直接記載されていた
- これは基本設計または詳細設計レベルの決定事項であり、要件定義としては粒度が細かすぎる

**対応結果**

- 要件定義書では「サーバーサイド API 経由で送信する」ことのみを要件化
- 使用する送信サービスや実装基盤は基本設計書で確定する方針に変更
- セキュリティ要件も、特定実装名ではなく「送信頻度制御」として一般化

### 5. ステータス表示が実態と合っていなかった

**指摘内容**

- 未解決の整合性問題がある状態で `レビュー済み` になっていた

**対応結果**

- 要件定義書のステータスを `レビュー反映済み` に変更

## 残課題

今回の修正対象は要件定義書本体であり、以下の関連文書は未更新。

- `work/CMS_Shopifyとの併用案.txt`
- `work/実装差異調査結果.md`

特に以下は表記差異として残る。

- 商品カテゴリURL
  - 要件定義書: `/products/category/[category]`
  - 併用案・差異調査: `/products/[category]`
- 予約導線
  - 要件定義書: `/kominka` 内リンク
  - 併用案・差異調査: `/facebook-reservation` または外部導線

後続の基本設計書、詳細設計書、実装タスク作成時には、今回確定した要件定義書の記載を正本として同期する必要がある。
