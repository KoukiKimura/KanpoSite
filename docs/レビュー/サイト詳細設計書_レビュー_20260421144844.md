### Major-01: SEO 実装詳細が上位設計に対して不足している

**対象箇所**

- `docs/サイト設計/サイト詳細設計書.md:625`
- `docs/サイト設計/サイト詳細設計書.md:627`

- `docs/サイト設計/サイト基本設計書.md:86`
- `docs/サイト設計/サイト基本設計書.md:370`
- `docs/サイト設計/サイト基本設計書.md:670`
- `docs/サイト設計/サイト基本設計書.md:672`
- `docs/要件定義/サイト要件定義書.md:339`
- `docs/要件定義/サイト要件定義書.md:342`

**内容**

詳細設計書の SEO セクションは `title` 例と構造化データの対象一覧に寄っており、要件定義書・基本設計書で要求されている以下が落ちている。

- `description` の生成元
- `canonical` の生成規則
- `og:image` の優先順位
- `trailingSlash: true` 前提の URL 正規化
- `sitemap.xml` の生成タイミングと出力対象

基本設計書では canonical と sitemap を末尾スラッシュありで統一すると明記されているが、詳細設計書 9 章ではそこまで落ちていない。このままだと `generateMetadata` 実装や sitemap 生成の仕様が実装者依存になる。

**推奨対応**

9.1 に少なくとも次を追加する。

- `description` の優先順位
- `canonical` の生成式
- `og:image` の優先順位
- 末尾スラッシュ統一ルール
- `sitemap.xml` の生成責務

### Major-02: `preview/page/home` がホーム構成要素を全てカバーしていない

**対象箇所**

- `docs/サイト設計/サイト詳細設計書.md:80`
- `docs/サイト設計/サイト詳細設計書.md:85`
- `docs/サイト設計/サイト詳細設計書.md:86`
- `docs/サイト設計/サイト詳細設計書.md:100`
- `docs/サイト設計/サイト詳細設計書.md:106`
- `docs/サイト設計/サイト詳細設計書.md:107`
- `docs/サイト設計/サイト詳細設計書.md:118`
- `docs/サイト設計/サイト詳細設計書.md:527`
- `docs/サイト設計/サイト詳細設計書.md:532`

**内容**

`preview/page/home` は `site_settings` と `top_feature` を組み合わせてトップページを確認する方針になっているが、トップページの実データ源はそれだけではない。

トップページには少なくとも以下が含まれる。

- `farm_page`
- `kominka_page`
- `story`
- `news`
- `Shopify` の注目商品

現行設計では `farm_page` や `kominka_page` の変更がホーム上のバナー表示にどう反映されるか、home preview で未公開内容をどう差し替えるかが定義されていない。結果として、ホーム preview と個別ページ preview で確認結果がズレる可能性がある。

**推奨対応**

次のどちらかに寄せるべき。

- `pageKey=home` で home 構成に使う全コンテンツの draft 差し替えルールを定義する
- home preview は `site_settings` / `top_feature` のみ対象とし、その他は個別 preview で確認すると明記する

今の文面だと「home preview でトップページ全体を確認できる」と読めるため、対象範囲を明文化した方がよい。

### Major-03: `site_settings` にホーム本文を入れたことで上位文書との責務がずれている

**対象箇所**

- `docs/サイト設計/サイト詳細設計書.md:100`
- `docs/サイト設計/サイト詳細設計書.md:101`
- `docs/サイト設計/サイト詳細設計書.md:481`
- `docs/サイト設計/サイト詳細設計書.md:487`
- `docs/サイト設計/サイト詳細設計書.md:490`
- `docs/サイト設計/サイト基本設計書.md:260`
- `docs/要件定義/サイト要件定義書.md:331`

**内容**

詳細設計書では `site_settings` に `homeHeroTitle`、`homeHeroLead`、`homeHeroImage`、`homeIntroText` を追加して、ホームページ固有コンテンツを持たせている。

しかし要件定義書・基本設計書では `site_settings` は共通設定として整理されており、列挙されているのは `siteName`、`siteDescription`、`ogpDefaultImage`、`contactEmail`、`socialLinks` までである。

詳細設計で勝手に拡張した状態になっているため、以下の問題が残る。

- 上位文書とのスキーマ差分が発生している
- `site_settings` が「共通設定」なのか「ホームページ本文も持つシングルページ」なのか曖昧になる
- 将来 `home_page` のような専用コンテンツ型に分離したくなった時に戻しが発生する

**推奨対応**

どちらかに統一するべき。

- 上位文書も更新し、`site_settings` にホーム固有項目を正式採用する
- `home_page` シングルコンテンツを新設し、`site_settings` は共通設定に戻す

責務分離の観点では後者の方が自然。

### Major-04: `CartDrawer` の状態設計に `line items` がなく、描画元が曖昧

**対象箇所**

- `docs/サイト設計/サイト詳細設計書.md:218`
- `docs/サイト設計/サイト詳細設計書.md:336`
- `docs/サイト設計/サイト詳細設計書.md:514`
- `docs/サイト設計/サイト詳細設計書.md:520`
- `docs/サイト設計/サイト詳細設計書.md:523`
- `docs/サイト設計/サイト詳細設計書.md:535`
- `docs/サイト設計/サイト詳細設計書.md:542`
- `docs/サイト設計/サイト基本設計書.md:271`

**内容**

`CartDrawer` は商品一覧表示、数量変更、削除、checkout 遷移を担当するが、状態管理で定義されているのは以下だけである。

- `cartId`
- `itemCount`
- `subtotalAmount`
- `checkoutUrl`

これでは drawer 内の商品行を何から描画するのかが定義されていない。基本設計書では「クライアントサイドでカート ID と line items を保持する」としているため、詳細設計との間に差がある。

現状の記述だと、以下のどちらで実装するのか読めない。

- `CartDrawer` を開くたびに `cartId` から `Shopify cart` を再取得して line items を描画する
- React state に line items を保持し、操作のたびに同期更新する

**推奨対応**

6.1 か 6.3 に次を追記する。

- `lineItems` の保持先
- 初回取得タイミング
- 数量変更・削除後の更新方法
- localStorage には保持しないのか、直近 snapshot を持つのか

`CartDrawer` はフェーズ1の主要導線なので、ここは詳細設計の粒度まで落としておいた方がよい。

優先順位は次の通り。

1. SEO 詳細を 9 章に落とす
2. home preview の対象範囲を固定する

4. `CartDrawer` の `line items` 状態設計を明記する
