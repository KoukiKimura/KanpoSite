## 指摘事項

### Major-01: 古民家ページのヒーローで `SectionHeading` の `h2` がほぼ不視認

**対象ファイル**

- `web_mock/src/app/kominka/page.tsx`
- `web_mock/src/components/ui/SectionHeading.tsx`

**内容**

`kominka/page.tsx` のヒーローセクションは `bg-[#33281f]`（濃いこげ茶）で描画されている。その中で `SectionHeading` を使っているが、`SectionHeading` の `<h2>` は `text-mock-ink`（`#1d241c`）を固定で適用している。

背景色 `#33281f` と文字色 `#1d241c` のコントラスト比は約 **1.35:1** であり、WCAG 2.1 AA 基準（大文字 3:1 以上）を大きく下回る。タイトルが依頼者に全く読めない状態になっている。

```tsx
// kominka/page.tsx — ヒーロー（bg-[#33281f] 暗背景）
<SectionHeading
  eyebrow="Kominka mock"
  title="宿泊ページは静かに、しかし不安なく"  // この h2 が #1d241c → 視認不可
  description={mockKominka.lead}
  align="left"
/>
```

```tsx
// SectionHeading.tsx — h2 に text-mock-ink が固定
<h2 className="font-serif text-3xl leading-tight text-mock-ink md:text-5xl">
```

**推奨対応**

案1: `SectionHeading` に `light` prop を追加し、暗背景向けの配色（`text-white` / `text-mock-paper`）へ切り替えられるようにする。

```tsx
// SectionHeading.tsx に light?: boolean を追加
const headingColor = light ? 'text-mock-paper' : 'text-mock-ink';
const bodyColor    = light ? 'text-white/80'    : 'text-mock-muted';
```

案2: `kominka/page.tsx` のヒーロー内の文字色を親コンテナで上書きする。

```tsx
<div className="space-y-6 [&_h2]:text-mock-paper [&_p]:text-white/80">
  <SectionHeading ... />
</div>
```

### Major-02: 商品詳細の CTA ボタンが `<span>` 要素

**対象ファイル**

- `web_mock/src/app/products/[slug]/page.tsx`（該当箇所 2 件）

**内容**

商品詳細ページに "Add to mock cart" と "Review purchase flow" の 2 つの CTA があるが、どちらも `<span>` 要素で実装されている。`<span>` はキーボードフォーカスを受け付けず、スクリーンリーダーで操作不能になる。モックとはいえ、依頼者がタブキー操作で確認する際に CTA がスキップされる。

```tsx
// 現状 — span 要素
<span className="mock-button-primary">Add to mock cart</span>
<span className="mock-button-secondary">Review purchase flow</span>
```

**推奨対応**

`<button type="button">` に変更する。

```tsx
<button type="button" className="mock-button-primary">Add to mock cart</button>
<button type="button" className="mock-button-secondary">Review purchase flow</button>
```

### Minor-01: Google Fonts を `<link>` タグで直接読み込んでいる（ESLint 警告）

**対象ファイル**

- `web_mock/src/app/layout.tsx`

**内容**

`layout.tsx` の `<head>` 内に Google Fonts の `<link>` タグを 3 本直接記述している。これにより ESLint（`@next/next/no-page-custom-font`）が Warning を出力している。

```
./src/app/layout.tsx
47:9  Warning: Custom fonts not added in `pages/_document.js` will only load
      for a single page. @next/next/no-page-custom-font
```

Next.js App Router では `next/font/google` を使うことで、フォント CSS のインライン化・FOUT 防止・Google サーバーへのリクエスト削減が実現できる。モックとはいえ `next lint` でのクリーン実行を保つために対応が望ましい。

**推奨対応**

```tsx
// layout.tsx
import { Cormorant_Garamond, Noto_Sans_JP, Noto_Serif_JP } from 'next/font/google';

const cormorant = Cormorant_Garamond({ subsets: ['latin'], weight: ['400','500','600'], variable: '--font-cormorant' });
const notoSans  = Noto_Sans_JP({ subsets: ['latin'], weight: ['300','400','500'], variable: '--font-noto-sans' });
const notoSerif = Noto_Serif_JP({ subsets: ['latin'], weight: ['400','500','600'], variable: '--font-noto-serif' });

// <html> に variable クラスを付与し、tailwind.config.ts のフォントファミリーを CSS 変数参照に変更する
```

### Minor-02: Contact フォームの `<input>` / `<select>` / `<textarea>` に `name` 属性がない

**対象ファイル**

- `web_mock/src/app/contact/page.tsx`

**内容**

フォーム要素すべてに `name` 属性がない。また「メールアドレス」の `<input>` に `type="email"` が指定されておらず、モバイルブラウザでのメールキーボード最適化が効かない。

現在はモックのため送信機能がなく実害はないが、設計書（詳細設計書 3.8 節）の入力項目定義（`name`, `email`, `phone`, `message`, `category`）と対応付けを明示しておくと、将来の `web/` 実装への移行判断が容易になる。

**推奨対応**

```tsx
// name フィールド
<input name="name" type="text" ... />

// メールフィールド
<input name="email" type="email" ... />

// 種別セレクト
<select name="category" ... >

// メッセージ
<textarea name="message" ... />
```

### Minor-03: `Footer.tsx` と `not-found.tsx` でバッククォートが本文中に露出

**対象ファイル**

- `web_mock/src/components/layout/Footer.tsx`
- `web_mock/src/app/not-found.tsx`

**内容**

フッターと 404 ページの本文に `\`web_mock/\`` のようにバッククォートで括ったテキストが HTML としてそのままレンダリングされる。開発者向けメモとしては有用だが、依頼者が閲覧した際に記号文字が混在して見えるため、世界観の演出が崩れる。

```tsx
// Footer.tsx
<p className="max-w-2xl leading-8">
  `web_mock/` は依頼者レビュー用の静的モックです。...
</p>

// not-found.tsx
<p>
  `web_mock/` は依頼者レビュー用の最小ひな形です。...
</p>
```

**推奨対応**

依頼者向けの表示テキストとして自然な文言に変更する。バッククォートの代わりに `<code>` タグを使うか、単純に削除する。

```tsx
// Footer.tsx 案
<p className="max-w-2xl leading-8">
  このサイトは依頼者レビュー用の静的モックです。実データ接続、問い合わせ送信、
  在庫確認、決済遷移は含みません。
</p>
```

## Info

### Info-01: `package.json` の `"export"` スクリプトが `"build"` と同一

`next.config.mjs` に `output: 'export'` が設定済みであるため、`next build` を実行するだけで静的エクスポートが完了する。`"export": "next build"` スクリプトは `"build"` と等価で冗長。CI や README から混乱なくビルドできるよう、削除を推奨する。

---

### Info-02: `mockSite.referenceDesign` に参照先の外部 URL がソースコード中に記述

`web_mock/src/lib/mock/site.ts` に `referenceDesign: 'https://www.roccadeifiori.eu/en/the-company/'` が含まれている。`web_mock/` 専用の定数であるため現時点では問題ないが、将来 `web/` へモジュールを誤移植した場合に著作権上の注意が必要になる。コメントに「参照用・誤移植注意」の旨を記載しておくことを推奨する。

---

### Info-03: 古民家ページに予約導線の外部リンクが未設置

`kominka/page.tsx` の予約説明セクションには「予約方法を説明する構成」としてテキストのみが置かれ、実際のリンク要素（`<a href="...">` または外部予約 URL）がない。設計書（詳細設計書 3.7 節）では「予約リンクは各ページの CTA として配置する」とあり、モック段階でもリンク先 URL のプレースホルダー（`href="#"` 等）を置いて導線の位置・見せ方を確認できる状態にすることが望ましい。

---

### Info-04: ヘッダーナビゲーション項目が本番設計と異なる（意図的差分として記録）

`Header.tsx` のナビゲーションは `Top`・`Products`・`Kominka`・`Contact` の 4 項目のみ。設計書（基本設計書 4.2 節）の本番ナビには `ブランド`・`畑`・`ストーリー`・`お知らせ` 等が追加で含まれる。`web_mock/` の実装ルートは 5 ページのみなので差分は設計の意図通りだが、本番実装時に設計書のナビ構成を再確認することを推奨する。
