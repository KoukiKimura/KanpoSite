## 1. レビュー観点

- Shopify案の要件定義・基本設計と矛盾していないか
- ユーザー指定の「ローカルでテーマ作成、ZIP化、Shopify管理画面へアップロード、反映」フローが主導線になっているか
- ZIPアップロード後の調整、商品登録、SEO対策、ブログ更新方法が順序立っているか
- Shopify公式仕様と齟齬がないか
- ルートID、テンプレート、GA4、セキュリティ、テーマ設定の記述に実装上の誤解がないか

---

## 2. 第1回レビュー指摘と反映

| 指摘 | 反映 |
|---|---|
| テーマ反映が `shopify theme push` 前提で、ユーザー指定のZIPアップロード手順とずれていた | 正規手順を `shopify theme package` によるZIP生成とShopify管理画面アップロードへ変更 |
| ZIPアップロード後の調整、商品登録、SEO、ブログ更新の作業順が不足していた | `8. テーマ作成・Zip反映・運用立ち上げ設計` を追加し、全体作成イメージ、アップロード後調整、商品登録、SEO、ブログ更新を詳細化 |
| ルーティング表で `P10` が複数回使われていた | `P10` から `P17` まで一意になるよう修正 |
| `assets/base.css` に Liquid 変数を直接書くように読め、Shopifyテーマ実装として誤解があった | Liquid値は `theme.liquid` またはsnippet内の `<style>` でCSS変数化し、静的CSSは変数参照にする方針へ修正 |
| GA4をテーマへ直接埋め込む前提が強く、Shopify標準連携との二重計測リスクがあった | Google & YouTubeチャネル等の標準連携を優先し、テーマ側は不足するカスタムイベントのみ発火する方針へ修正 |
| ZIPファイルが商品・ブログ・ページ等のストアデータを含まない点が明確でなかった | ZIPに含めるもの / 含まれないものを表で明記 |

---

## 3. 第2回レビュー指摘と反映

| 指摘 | 反映 |
|---|---|
| `layout/theme.liquid` の設計例に `GA4 gtag.js` とあり、直接埋め込み推奨に見える | 「標準GA4連携で不足するカスタムイベントJS（必要時のみ）」へ修正 |
| セキュリティヘッダーをテーマ側で個別制御できるように読めた | Shopify標準配信に依存し、テーマコードから任意HTTPヘッダーは制御できない旨に修正 |
| `settings_data.json` がディレクトリ構成ではGit管理対象、運用方針では任意となっていた | 「Git管理有無は方針に従う」に統一 |
