## レビュー観点

- Shopify上でトップ、商品、カート、古民家、問い合わせ、ブログ、法務ページが完結すること
- 独自Next.js公開サイト、ConoHa静的配信、外部ECリンク運用が現行仕様に残っていないこと
- Shopify標準機能、テーマカスタマイズ、AI支援開発、Shopify CLI反映の境界が明確であること
- モック再現、Checkout制約、問い合わせ標準フォーム、古民家予約外部リンクの扱いがロードマップに落ちていること
- ブログをShopifyアプリからスマホ投稿できる前提が、実機確認タスクとして管理されていること
- SEO、画像最適化、認証情報管理、公開前確認、ロールバックが漏れていないこと

## 1周目の指摘と反映

| 指摘 | 反映 |
|---|---|
| 必須ページにカートがなく、Checkout導線の確認範囲が弱い | 要件定義に `/cart` を追加し、ロードマップにカートページまたはカートドロワー確認タスクを追加 |
| 画像が重い場合の表示速度・SEO対策が弱い | Shopify CDN、responsive image、lazy loading、過大画像回避、画像速度確認タスクを追加 |
| Shopify CLI / Admin API利用時の認証情報管理が明文化されていない | 認証情報をリポジトリへ保存しない方針と管理タスクを追加 |
| 問い合わせ送信先の確認が曖昧 | ストア通知先・差出人メール設定の確認を要件とタスクに追加 |
| スマホブログ投稿が要件止まりで、運用実機確認タスクが弱い | Shopifyアプリ、運営者権限、画像投稿、下書き保存・公開予約の確認タスクを追加 |
| 公開前の本番相当確認と差し戻し手順が不足 | カート、Checkout、決済、配送、法務、問い合わせ、テーマ公開・ロールバック手順を追加 |

## 2周目の指摘と反映

| 指摘 | 反映 |
|---|---|
| ロードマップのフェーズ3・4の目的と完了条件に、追加したカート・注文テストが反映されていない | フェーズ3にカート、フェーズ4に注文テストを追加 |
| Shopifyブログの正規URLが `/blogs/stories` として記載されているが、作成・確認タスクが不足 | ブログURL方針確認タスクと、handle `stories` の作成タスクを追加 |
| `/blog` を使いたい場合の扱いが未整理 | 初期正規URLは `/blogs/stories` とし、必要時のみ `/blog` 導線またはリダイレクトを別途扱う方針を追加 |

## 最終確認

- 現行仕様はShopify Online Store、Online Store 2.0テーマ、Liquid / JSON sections、Shopify CLI反映に統一されている。
- Next.js、ConoHa、外部ECリンクは初期対象外または比較対象としてのみ記載され、現行構成には含まれていない。
- 主要ページ、カート、Checkout、問い合わせ、ブログ、古民家外部予約、法務、SEO、画像、認証情報、公開手順が要件とロードマップの双方に反映済み。
- `BASE` 方針の残存はない。

## 残指摘

なし。
