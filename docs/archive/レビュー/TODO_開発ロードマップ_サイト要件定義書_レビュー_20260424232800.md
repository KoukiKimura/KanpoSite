## Critical

### Critical-01: コンテンツ更新機能の扱いが文書内で矛盾している

**対象**: `docs/要件定義/サイト要件定義書.md`

- 30行目: 運営者がコードを触らずに記事、FAQ、写真、古民家情報を更新できる運用を実現すると記載
- 38行目、109行目、116行目、242行目、266行目、469行目: `DecapCMS` はSEO専用で、ユーザーによるコンテンツ更新機能や記事・FAQ・古民家情報更新はスコープ外と記載
- 159行目、193行目: トップの特集枠・バナー・写真、ブランド画像・文章をCMSで更新できる旨の記載

**問題**

初期リリースで「CMSによるコンテンツ更新」を実現するのか、将来フェーズに送るのかが文書内で矛盾している。  
このままだと、記事・お知らせ・古民家・トップ特集を静的ファイルで持つのか、DecapCMSに持たせるのか、初期から microCMS を必要とするのかが判断できない。

**推奨対応**

初期リリースの方針を以下のいずれかに統一する。

1. 初期はコンテンツ更新機能なし: 記事・FAQ・古民家・トップ特集は静的データで管理し、運営者更新は将来 `microCMS` 移行後と明記する
2. 初期から一部更新あり: `DecapCMS` の責務をSEO専用から拡張し、管理対象コンテンツ型と更新範囲を明記する

現行の「DecapCMS は SEO 専用」を維持するなら、30行目、159行目、193行目は修正が必要。

### Critical-02: フェーズ4・5の完了条件が現行方針と矛盾している

**対象**: `docs/TODO_開発ロードマップ.md`

- 45〜46行目: 現行方針は `DecapCMS` / `BASE`
- 60行目: フェーズ4完了条件が `microCMS` と `Shopify` の実データ表示
- 61行目: フェーズ5完了条件が複数商品カートを含む
- 133行目: サイト内カートは不要と記載

**問題**

フェーズ一覧の完了条件が旧方針のまま残っている。現行方針では、初期実装のECは `BASE` への外部リンクであり、サイト内カートも `Shopify` 実データ連携も初期完了条件ではない。

**推奨対応**

フェーズ4の完了条件は「`DecapCMS` のSEO補助情報、静的商品データ、BASE外部リンク、`preview/` 下書き確認を表示する」などに修正する。  
フェーズ5の完了条件は「問い合わせ、BASE外部リンク導線、デプロイ、確認フローを含めて運用可能にする」に修正する。

## Major

### Major-01: 記事・お知らせ・古民家ページの本文データソースが未確定

**対象**: `docs/要件定義/サイト要件定義書.md`

- 127〜134行目: トップ、ストーリー、お知らせの主データが `DecapCMS（SEO情報）`
- 139〜141行目: 古民家関連ページの主データが `CMS`
- 116行目、469行目: コンテンツ更新機能はスコープ外
- 242行目、266行目: `DecapCMS` はSEO補助情報のみ

**問題**

ページ本文や一覧データの正本が定義されていない。SEO情報だけでは、ストーリー本文、お知らせ本文、古民家説明、アクセス情報、体験内容を生成できない。

**推奨対応**

ページ一覧の「主データ」を初期リリース前提に合わせて修正する。例:

- ストーリー・お知らせ・FAQ・古民家: `静的データ（将来: microCMS）`
- SEO補助情報: `DecapCMS`

あわせて、静的データの配置場所とデータ形式は基本設計書または詳細設計書に委譲する旨を追記する。

### Major-02: 問い合わせ通知先 `site_settings.contactEmail` が現行 DecapCMS 設定に存在しない

**対象**: `docs/要件定義/サイト要件定義書.md`、`docs/TODO_開発ロードマップ.md`

- TODO 132行目、165行目: 通知先は `DecapCMS` の `site_settings.contactEmail` を正本とする
- 要件定義書 330行目: 現行 DecapCMS の `site_settings` は `siteName`, `siteDescription`, `ogpDefaultImage`, `socialLinks`
- 要件定義書 344行目: `contactEmail` は将来 `microCMS` の完全版 `site_settings` にのみ記載

**問題**

問い合わせ通知先を `DecapCMS site_settings.contactEmail` から取得するタスクがあるが、要件定義書上の現行 DecapCMS 設定に `contactEmail` が含まれていない。実装時に通知先の正本が不明になる。

**推奨対応**

初期から問い合わせ通知先を DecapCMS で管理するなら、現行 `site_settings` に `contactEmail` を追加する。  
DecapCMS をSEO専用に限定するなら、通知先は環境変数または PHP API 側設定を正本とし、TODO 132行目・165行目を修正する。

### Major-03: `DecapCMS` を API として扱う記述が Git ベース運用と不整合

**対象**: `docs/要件定義/サイト要件定義書.md`

- 243行目: `DecapCMS` は Git リポジトリベースで動作すると記載
- 245行目: `DecapCMS` のAPIがビルド時に応答しない場合のエラーハンドリングと記載

**問題**

DecapCMS は通常、リポジトリ内のファイルを編集・コミットする管理UIであり、ビルド時に外部CMS APIから取得する前提とは異なる。  
この記述は `microCMS` 時代の API 取得方針が残っている可能性が高い。

**推奨対応**

245行目は「SEO設定ファイルの欠落・構文不正・必須項目不足時のビルド時エラーハンドリング」に修正する。将来 `microCMS` 移行時の API 障害対応は別項目として切り分ける。

### Major-04: セキュリティ要件に `Shopify` 決済情報の記述が残っている

**対象**: `docs/要件定義/サイト要件定義書.md`

- 417行目: `Shopify` の決済情報をサイト側で保持しない（決済は `BASE` に委譲）

**問題**

現行ECは `BASE` であり、文中の主語だけ `Shopify` が残っている。意味としては BASE 決済情報の非保持を示すべき。

**推奨対応**

「`BASE` の決済情報をサイト側で保持しない（決済は `BASE` に委譲）」に修正する。将来 Shopify 移行時も同様に決済情報非保持とするなら、その補足を別文で追記する。

### Major-05: 旧カート方針がタスク・判断メモ・更新履歴に残っている

**対象**: `docs/TODO_開発ロードマップ.md`

- 61行目: 複数商品カートを完了条件に含めている
- 101行目: ヘッダーのカート件数表示とカートドロワー前提のUI
- 133行目: サイト内カートは不要
- 161行目: `CartDrawer` で checkout へ導線
- 185行目: 複数商品カート前提へ更新

**問題**

現行方針では `BASE` 商品ページへの外部リンク遷移であり、サイト内カート・カート件数表示・カートドロワーは不要。旧方針が残ることで、ヘッダーや商品詳細の実装範囲が過大になる。

**推奨対応**

カート関連タスクは削除または将来 `Shopify` 移行時の保留項目へ移動する。初期フェーズのタスクは「BASE外部リンクボタン」「外部リンクであることの明示」「GA4のBASE購入導線クリック計測」に置き換える。
