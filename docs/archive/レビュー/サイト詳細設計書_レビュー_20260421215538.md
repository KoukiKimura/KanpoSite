## 指摘事項

### Major-01: `preview/` が `home preview` 用の `Shopify` 接続情報を持っていない

**対象箇所**

- `docs/サイト設計/サイト詳細設計書.md:90`
- `docs/サイト設計/サイト詳細設計書.md:107`
- `docs/サイト設計/サイト詳細設計書.md:122`
- `docs/サイト設計/サイト詳細設計書.md:601`
- `docs/サイト設計/サイト詳細設計書.md:622`
- `docs/サイト設計/サイト詳細設計書.md:838`
- `docs/サイト設計/サイト詳細設計書.md:842`
- `docs/サイト設計/サイト基本設計書.md:624`
- `docs/サイト設計/サイト基本設計書.md:625`

**内容**

詳細設計書では、`preview/page/home` でも注目商品は `Shopify` の公開済みデータを使う前提になっている。

しかし `11.2 preview/` の環境変数には `microCMS` と preview 保護用の値しかなく、`Shopify Storefront API` に接続するための `NEXT_PUBLIC_SHOPIFY_STORE_DOMAIN` と `NEXT_PUBLIC_SHOPIFY_STOREFRONT_ACCESS_TOKEN` が定義されていない。

このままだと、`home preview` を別アプリとして実装する際に注目商品セクションだけ描画手段が不足する。詳細設計上は「公開済み商品データを併用する」と書かれているが、どこからそれを取得するのかが閉じていない。

**推奨対応**

次のいずれかを詳細設計で明記する。

- `preview/` にも `NEXT_PUBLIC_SHOPIFY_STORE_DOMAIN` と `NEXT_PUBLIC_SHOPIFY_STOREFRONT_ACCESS_TOKEN` を持たせる
- `preview/` は `web/` 側で生成した商品フィードを参照する
- `home preview` では注目商品セクションを省略し、下書き確認対象外とする

現状の記述だと 1 案が最も自然で、基本設計書 8.7 の想定設定値とも整合しやすい。

### Major-02: 画像SEOで必要な `alt` / OGP画像代替テキストの取得方針が未定義

**対象箇所**

- `docs/要件定義/サイト要件定義書.md:304`
- `docs/要件定義/サイト要件定義書.md:309`
- `docs/要件定義/サイト要件定義書.md:375`

- `docs/サイト設計/サイト詳細設計書.md:417`
- `docs/サイト設計/サイト詳細設計書.md:427`
- `docs/サイト設計/サイト詳細設計書.md:432`
- `docs/サイト設計/サイト詳細設計書.md:451`
- `docs/サイト設計/サイト詳細設計書.md:453`
- `docs/サイト設計/サイト詳細設計書.md:466`
- `docs/サイト設計/サイト詳細設計書.md:471`
- `docs/サイト設計/サイト詳細設計書.md:490`
- `docs/サイト設計/サイト詳細設計書.md:494`

**内容**

要件定義書では `OGP画像の代替テキスト` と `すべての主要画像に alt テキストを設定する` ことが明記されている。

一方、詳細設計書の `microCMS` データモデルでは、各コンテンツの画像項目は `media` や `repeater(media)` として定義されているだけで、次のどちらで `alt` を担保するのかが書かれていない。

- `microCMS` のメディア自体に持つ代替テキストを利用する
- `heroImageAlt`、`ogpImageAlt`、ギャラリー画像ごとの説明フィールドを別に持つ

現状のままだと、実装者が `alt=""` を多用するのか、CMS スキーマを後から増やすのかが未確定で、要件 6.4 / 7.5 を設計として満たしていない。

**推奨対応**

詳細設計書で画像の代替テキスト方針を固定する。

- `story` / `news`: `ogpImageAlt`
- `about_page` / `concept_page` / `farm_page`: `heroImageAlt`, 必要に応じてギャラリー画像の `alt`
- `kominka_page` / `kominka_experience`: ギャラリー画像ごとの `alt`
- `site_settings.logo`: `logoAlt`

もし `microCMS` メディア標準の代替テキスト機能を使うなら、その前提を明記し、各 `media` フィールドで入力必須にする運用ルールまで書くべきである。

### Minor-01: `ArticleMeta` の `カテゴリ` 表示に対する入力源が曖昧

**対象箇所**

- `docs/サイト設計/サイト詳細設計書.md:153`
- `docs/サイト設計/サイト詳細設計書.md:354`
- `docs/サイト設計/サイト詳細設計書.md:373`
- `docs/サイト設計/サイト詳細設計書.md:396`

**内容**

`ArticleMeta` の役割は「公開日、更新日、著者または運営主体、カテゴリ」とされている。

しかし `story` と `news` のデータモデルには `category` 相当のフィールドがなく、記事詳細の表示仕様でもカテゴリ表示の出どころが定義されていない。ここで言う `カテゴリ` が

- `story` / `news` という記事種別ラベルなのか
- CMS 入力項目としてのカテゴリなのか

が曖昧である。

**推奨対応**

次のどちらかに寄せて記述を固定する。

- `ArticleMeta` の `カテゴリ` は CMS 項目ではなく、`story` / `news` の記事種別ラベルを表示する
- `story` / `news` に `categoryLabel` などの項目を追加する

要件上必須の項目ではないため重大ではないが、UI 実装時の認識ずれは起こしやすい。

---

## 結論

v1.4.2 は実装着手レベルに近づいているが、まだ `preview/` の `Shopify` 接続条件と画像 `alt` 設計が閉じていない。

優先順位は次のとおり。

1. `preview/` に `Shopify` 公開データをどう渡すか確定する
2. 画像 `alt` / OGP画像代替テキストの入力方式を定義する
3. `ArticleMeta` の `カテゴリ` を記事種別ラベルにするか CMS 項目にするか決める
