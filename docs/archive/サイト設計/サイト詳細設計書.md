## 1. 詳細設計前提

- 公開サイトは `web/` アプリで実装し、`Next.js Static Export` により `ConoHa WING` の本番 / 検証環境へ配備する
- 依頼者レビュー用のモックは `web_mock/` 別アプリで実装し、ダミーデータによる静的表示に限定する
- 初期リリースでは `preview/` 別アプリを作成しない。下書き確認は将来 `microCMS` 移行時に再検討する
- 初期リリースの本文系コンテンツ、商品表示コピー、FAQ、古民家情報、トップ特集は静的データで管理する
- `DecapCMS` はSEO補助情報のみを管理する
- 商品主データ、価格、在庫、決済、注文、配送・返品等のEC運用条件は `BASE` を正本とする
- 商品詳細の購入導線は `BASE` 商品ページへの外部リンクとし、サイト内カート、カート件数、カートドロワー、チェックアウトは実装しない
- 問い合わせは `contact-api/` 配下の `PHP` API で処理し、通知先は環境変数または PHP API 側設定を正本とする

### 1.1 アプリ構成

| アプリ / モジュール | 役割 | 実行基盤 |
|---|---|---|
| `web_mock/` | 依頼者確認用の静的モック、ダミーデータ表示 | 静的ホスティング |
| `web/` | 公開サイト本体、静的HTML生成、SEO出力 | `ConoHa WING` |
| `contact-api/` | 問い合わせ送信、レート制御、通知メール送信 | `ConoHa WING` |

### 1.2 環境構成

| 環境 | 配備対象 | 用途 |
|---|---|---|
| `mock_review` | `web_mock/` | 依頼者向けデザイン確認 |
| `production` | `web/` + `contact-api/` | 本番公開 |
| `staging` | `web/` + `contact-api/` | 結合確認、問い合わせ送信確認、BASE外部リンク確認 |

## 3. 画面詳細設計

### 3.1 トップページ（`/`）

| セクション | 主データ | 内容 |
|---|---|---|
| Hero | 静的データ + `site_settings` | ブランドコピー、主導線 |
| Brand Intro | 静的データ | ブランドの短い説明 |
| Featured Products | 静的商品データ | 注目商品 3〜6件 |
| Stories Pickup | 静的記事データ | 新着記事 3件程度 |
| News Pickup | 静的お知らせデータ | お知らせ 3〜5件 |
| Farm Banner | 静的データ | 畑紹介への導線 |
| Kominka Banner | 静的データ | 古民家紹介への導線 |
| Footer CTA | 固定 | 商品一覧または古民家導線 |

仕様:

- 商品導線は商品詳細を経由して `BASE` 商品ページへ遷移する
- トップ特集は静的データで管理し、将来 `microCMS` の `top_feature` へ移行できる形にする
- 本文全文は出さず、カードにはタイトル、日付、サムネイル、抜粋を表示する

### 3.2 ブランド / コンセプト / 畑

| ページ | セクション |

仕様:

- 本文は静的データで管理する
- 写真ギャラリーは PC / SP でレイアウトを切り替える
- CTA は `商品を見る`、`ストーリーを見る` のように文脈依存で出し分ける

| 値 | 用途 |

レイアウト:

購買UI:

| 要素 | 仕様 |
|---|---|

| 在庫 | 初期リリースでは表示しない |

構造化データ:

- `Product`
- `Offer` は静的データで価格整合性を担保できる商品に限って出力する

| ページ | 主なセクション |
|---|---|

| `/kominka/access` | Hero、Address、Map、Parking、Access Note |

### 3.8 お問い合わせ

入力項目:

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| `category` | select | 必須 | 商品 / 配送 / 古民家 / その他 |
| `name` | text | 必須 | 1〜50 文字 |
| `email` | email | 必須 | 形式検証 |
| `phone` | text | 任意 | 10〜15 文字以内 |
| `message` | textarea | 必須 | 最大 1,000 文字 |
| `privacyConsent` | checkbox | 必須 | 送信前同意 |
| `honeypot` | hidden | 任意 | bot 判定用 |
| `recaptchaToken` | hidden/runtime | 任意 | 外部 CAPTCHA 有効時のみ |

送信フロー:

```txt
1. フロント入力
2. クライアント側で形式検証
3. NEXT_PUBLIC_CONTACT_API_URL へ POST
4. contact-api/ で privacyConsent / Origin / honeypot / rate-limit / 本文検証
5. SMTP で通知メール送信
6. 成功メッセージを表示
```

エラー表示:

- サンクスページは作らず、同一ページ内で完了状態へ切り替える
- 失敗時は理由を一般化して表示し、代替連絡先リンクを併記する
- 内部パス、シークレット、個人情報を画面に出さない

### 3.9 法務ページ / 404

| ルート | 仕様 |
|---|---|
| `/shipping` | 配送条件、送料、発送目安。`BASE` 側を正本とする要約 |
| `/returns` | 返品条件、交換条件、連絡方法。`BASE` 側を正本とする要約 |
| `/legal` | 特商法表記。`BASE` 側設定と同期 |
| `/privacy` | 個人情報保護方針、Cookie、GA4利用方針 |
| `/terms` | 利用規約。EC運用条件と矛盾させない |
| `404.html` | トップ導線、商品一覧導線を持つ |

法務固定ページには `lastVerifiedAt` を持たせ、`BASE` 側設定と同期確認した日付を管理する。

## 6. contact-api 詳細設計

### 6.1 ディレクトリ構成

```txt
contact-api/
├── public/contact.php
├── src/bootstrap.php
├── src/validator.php
├── src/rate-limit.php
├── src/mailer.php
├── config/production.php
├── config/staging.php
└── var/
    ├── production/
    │   ├── logs/
    │   └── rate-limit/
    └── staging/
        ├── logs/
        └── rate-limit/
```

`var/` は公開Webルート外に置く。ホスティング制約で別配置が必要な場合も、ブラウザから直接参照できない場所に配置する。

### 6.2 リクエスト仕様

```json
{
  "category": "product",
  "name": "山田 太郎",
  "email": "sample@example.com",
  "phone": "090-1234-5678",
  "message": "お問い合わせ本文",
  "privacyConsent": true,
  "honeypot": "",
  "recaptchaToken": "optional-token"
}
```

### 6.3 レスポンス仕様

```json
{
  "ok": true,
  "message": "お問い合わせを受け付けました。",
  "errorCode": null
}
```

失敗時:

```json
{
  "ok": false,
  "message": "入力内容を確認してください。",
  "errorCode": "validation_error"
}
```

`errorCode`:

- `validation_error`
- `origin_forbidden`
- `spam_detected`
- `rate_limited`
- `mail_send_failed`
- `server_error`

### 6.4 レート制御

- キーは `IP + User-Agent` のハッシュで生成する
- 保存形式は `json`
- 保存先は `CONTACT_RATE_LIMIT_DIR`
- 期限切れファイルは送信時に簡易クリーンアップする
- rate-limit 情報は目的外利用しない

### 6.5 ログ

| 項目 | 仕様 |
|---|---|
| 保存先 | `CONTACT_LOG_DIR`。公開Webルート外 |
| ファイル名 | `YYYY-MM-DD.log` |
| 記録対象 | 成功、入力エラー、スパム判定、SMTP 失敗 |
| マスク | メールアドレス、電話番号は一部マスク |
| 本文 | 原則保存しない。保存が必要な場合は障害調査に必要な最小範囲に限定 |
| 保存期間 | 基本設計または運用手順で定める |

## 7. SEO / 構造化データ / 計測

### 7.1 metadata

- `description` は `seoDescription` を最優先とし、未設定時は静的データの summary、さらに未設定時は `site_settings.siteDescription` を使用する
- `canonical` は `NEXT_PUBLIC_SITE_URL + pathname + '/'` を基準に生成し、`trailingSlash: true` 前提で末尾スラッシュありに統一する
- `og:image` はページ個別 OGP を最優先とし、未設定時は `site_settings.ogpDefaultImage` を使用する
- `sitemap.xml` はビルド時に生成し、静的固定ページ、静的記事、静的商品ページを含める
- `robots.txt` は `DEPLOY_ENV=production` では `Allow: /`、`DEPLOY_ENV=staging` では `Disallow: /` とする
- `web_mock/` は依頼者レビュー専用のため `noindex` とし、本番 SEO の対象に含めない

### 7.2 構造化データ

| ページ | 型 |
|---|---|
| 全体 | `WebSite`, `Organization` |
| 商品詳細 | `Product`。`Offer` は価格整合性を担保できる商品に限る |
| 記事詳細 | `Article` |
| FAQ | `FAQPage` |
| 古民家 | `LocalBusiness` |
| パンくず表示ページ | `BreadcrumbList` |
