## レビュー観点

- オリジナル案が「Next.jsブランドサイト + Notionブログ + Shopify Storefront APIヘッドレスEC」として一貫していること
- 旧BASE外部リンク方針が現行仕様として残っていないこと
- Shopify案との境界が混ざっていないこと
- Notionのスマホ投稿要件、必須プロパティ、画像最適化、Static Export制約がロードマップに落ちていること
- Shopifyの商品取得、カート、Checkout、決済・注文管理の責務境界がロードマップに落ちていること
- セキュリティ、計測、SEO、公開前確認に未決事項が残っていないこと

## 1周目の指摘と反映

| 指摘 | 反映 |
|---|---|
| Shopify Storefront API方針に対して、フェーズ名がNotion中心でEC設計の位置付けが弱い | ロードマップのフェーズ0を `Notion・Shopify API設計` に変更 |
| 初期対象外に会員系機能の重複があり、スコープ表現が冗長 | 初期対象外を整理し、顧客マイページ・注文履歴・会員機能として統合 |
| Shopify Admin API tokenの扱いが、将来利用時の管理と公開禁止の境界として弱い | 要件定義のセキュリティ行で、Admin API tokenをブラウザに公開しない方針を明記 |
| GA4のEC計測で、Checkout後のpurchaseがサイト側実装なのか不明確 | `view_item`、`add_to_cart`、`begin_checkout` をサイト側対象、`purchase` はShopify Checkout側連携確認として明記 |
| 履歴上のBASE表記が現行仕様の残存に見える可能性がある | 更新履歴と判断メモを旧判断・当時の方針として明確化 |

## 2周目の確認結果

- 現行EC方針は `Shopify Storefront API`、Shopify Cart、Shopify Checkout遷移に統一されている。
- 決済、注文管理、配送、在庫、返品条件の正本はShopifyであり、サイト側の独自決済・独自注文管理は初期対象外になっている。
- `BASE` は更新履歴または旧判断メモにのみ残っており、現行仕様としては残っていない。
- `/blog` 正規化、`/blog/category/news` 統合、Notion必須プロパティ、画像最適化、再ビルド方式、未対応ブロック方針は要件定義とロードマップの双方に反映済み。
- Shopify商品、コレクション、metafields、Cart mutation、Checkout、APIエラー、在庫切れ、構造化データ、sitemap確認はロードマップに反映済み。
- セキュリティ、計測、公開前確認の境界は仕様文として明記済み。

## 残指摘

なし。
